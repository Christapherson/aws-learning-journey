## Solution Architecture

### Technology Decisions

**Why Serverless?**  
Chose AWS Lambda + DynamoDB + API Gateway (fully serverless stack) for:
- **Zero infrastructure management:** No EC2 instances to patch, scale, or monitor
- **Pay-per-use pricing:** Only charged for actual requests (not idle time)
- **Automatic scaling:** Handles 1-1,000+ concurrent requests without configuration
- **High availability:** Built-in redundancy across multiple AWS Availability Zones

**Why DynamoDB over RDS?**  
- Single-item lookups by partition key (`short_code`) complete in <10ms
- Auto-scaling handles read/write capacity without manual intervention
- Atomic operations prevent race conditions on `click_count` updates
- Serverless pricing model (no always-on database costs)

**Why API Gateway?**  
- Provides HTTPS endpoints without managing certificates
- Built-in request throttling and CORS support
- Integrates directly with Lambda (no additional infrastructure)
- Automatic request/response logging for debugging

### Architecture Flow

![URL Shortener Architecture](./images/url-shortener-architecture.png)

**CREATE Flow (POST /shorten):**
1. User submits long URL via POST request to API Gateway
2. API Gateway invokes `url-shortener-create` Lambda function
3. Lambda generates random 6-character short code
4. Lambda stores mapping in DynamoDB (short_code → long_url)
5. Returns short URL to user

**RETRIEVE Flow (GET /{short_code}):**
1. User visits shortened URL
2. API Gateway invokes `url-shortener-get` Lambda function
3. Lambda queries DynamoDB for matching short_code
4. Lambda atomically increments click_count
5. Returns 302 redirect to original long URL

### Key Implementation Details

**Short Code Generation:**
```python
# Generates cryptographically random 6-character codes
# 62^6 = 56.8 billion possible combinations (collision-resistant)
short_code = ''.join(random.choices(string.ascii_letters + string.digits, k=6))
```

**Atomic Click Tracking:**
```python
# UpdateItem with ADD operation prevents race conditions
# Multiple concurrent clicks correctly increment count
table.update_item(
    Key={'short_code': short_code},
    UpdateExpression='ADD click_count :inc',
    ExpressionAttributeValues={':inc': 1}
)
```

**Error Handling:**
- Returns 404 for non-existent short codes
- Returns 400 for missing/empty `long_url` in POST requests
- All errors include descriptive JSON messages

## Key Learnings

**What Worked Well:**
1. **Serverless removes operational burden:** No servers to patch, no databases to back up, no manual scaling. Deployment in minutes vs. hours with traditional infrastructure.

2. **DynamoDB partition key design is critical:** Using `short_code` as partition key enables single-digit millisecond lookups. A poor key choice (e.g., timestamp) would require expensive scans.

3. **API Gateway simplifies HTTP exposure:** Built-in HTTPS, CORS, throttling, and logging. Would've taken days to configure with EC2 + nginx.

4. **Error handling is non-negotiable:** Production APIs must handle invalid input gracefully. Returning descriptive error messages saved debugging time during testing.

**Challenges Overcome:**
1. **Understanding Lambda execution model:** Initially confused about invocation vs. execution. Learned that each request spawns isolated function instance, enabling true parallel execution.

2. **DynamoDB atomic operations:** First attempt used GetItem → increment → PutItem (race condition). Learned UpdateItem with ADD operation is atomic and prevents concurrent update bugs.

3. **CORS configuration:** Browser requests initially blocked. Added CORS headers to API Gateway, enabling cross-origin requests from web clients.

**What I'd Do Differently:**
1. **Add custom domain:** Current URL (`3xoo2ucyxk.execute-api...`) isn't user-friendly. Would use Route 53 + API Gateway custom domain for branded short URLs (e.g., `chris.link/abc123`).

2. **Implement expiration:** Add TTL (Time To Live) attribute to DynamoDB to auto-delete URLs after 90 days. Reduces storage costs and removes stale links.

3. **Add rate limiting:** Prevent abuse by limiting requests per IP address. Could use API Gateway usage plans or Lambda@Edge for this.

4. **Build simple frontend:** HTML form where users paste long URLs and get short URLs back. Would host on S3 + CloudFront (like my portfolio site).
