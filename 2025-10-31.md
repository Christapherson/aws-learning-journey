**Result:** HTTP 404, message: "Short URL not found" ✅

**Test 2: Missing Required Field**
```bash
curl -X POST https://3xoo2ucyxk.execute-api.us-east-2.amazonaws.com/prod/shorten \
  -H "Content-Type: application/json" -d '{}'
```
**Result:** Message: "long_url is required" ✅

**Test 3: Empty URL Value**
```bash
curl -X POST https://3xoo2ucyxk.execute-api.us-east-2.amazonaws.com/prod/shorten \
  -H "Content-Type: application/json" -d '{"long_url": ""}'
```
**Result:** Message: "long_url is required" ✅

### Key Learning: Error Handling Lives in Lambda

The error validation logic exists in the Lambda functions, not API Gateway or DynamoDB. Lambda checks:
- If required fields exist in the request
- If values are empty or null
- If database lookups return results

This is proper separation of concerns - API Gateway handles HTTP routing, Lambda handles business logic.

## Deep Dive: Lambda Concurrency Model

### Question I Had: "What's the difference between invocations and executions?"

**Invocations = Total count of function calls**
- No limit on total invocations (just pay per request)
- Example: 1 million invocations per day is fine

**Concurrent Executions = How many running at the same time**
- Default soft limit: 1,000 concurrent executions per region
- This prevents infinite scaling and runaway costs

**Real-World Scenario:**
- 1,000 users click shortened URLs simultaneously
- API Gateway invokes Lambda 1,000 times (1,000 invocations)
- Lambda spins up 1,000 function instances (1,000 concurrent executions)
- Each request completes in ~100ms
- All 1,000 requests succeed

**If 1,001st user clicks:**
- Request gets throttled (HTTP 429 error)
- Must wait until one of the 1,000 executions completes
- This is the soft limit protection mechanism

**Key Insight:** Concurrent executions = simultaneous running functions, NOT total calls over time.
