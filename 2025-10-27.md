## What I Learned

### DynamoDB Core Concepts

**NoSQL vs SQL:**
- **SQL (RDS):** Structured tables with fixed schemas, best for complex queries and JOINs
- **NoSQL (DynamoDB):** Flexible JSON documents, optimized for simple key-value lookups at massive scale

**Filing Cabinet Analogy:**
- DynamoDB table = one filing cabinet
- Items = folders in the cabinet
- Partition key = label on the folder (how you find it instantly)
- Attributes = papers inside the folder (can be different for each folder)

**Core Components:**
- **Table:** Container for items (like `url-shortener`)
- **Item:** Individual record (like one shortened URL mapping)
- **Partition Key:** Required unique identifier for fast lookups
- **Attributes:** Flexible properties (don't need to match across items)

**When to use DynamoDB:**
- Simple access patterns: "Give me item by ID"
- Unpredictable traffic that needs auto-scaling
- Serverless applications (integrates perfectly with Lambda)
- Fast <10ms lookups are critical

**When NOT to use DynamoDB:**
- Complex queries requiring JOINs across tables
- Heavy analytics and reporting
- Team already knows SQL and doesn't need NoSQL scale

### 3. Python CRUD Operations

**File:** `day-15-dynamodb/dynamodb_crud.py`

**Operations implemented:**

**CREATE (put_item):**
```python
table.put_item(
    Item={
        'short_code': 'abc123',
        'long_url': 'https://example.com/...',
        'created_at': datetime.now().isoformat(),
        'click_count': 0
    }
)
```
- Inserts new item or replaces entire item if it exists
- Like adding a new folder to the filing cabinet

**READ (get_item):**
```python
table.get_item(
    Key={'short_code': 'abc123'}
)
```
- Retrieves item by partition key
- Fast <10ms lookup
- Returns entire item with all attributes

**UPDATE (update_item):**
```python
table.update_item(
    Key={'short_code': 'abc123'},
    UpdateExpression='SET click_count = click_count + :val',
    ExpressionAttributeValues={':val': 1}
)
```
- Modifies specific attributes without replacing entire item
- **Atomic operation** = handles concurrent updates safely
- Like opening the folder and changing one paper inside

**DELETE (delete_item):**
```python
table.delete_item(
    Key={'short_code': 'abc123'}
)
```
- Removes item from table permanently

## Key Insights

### Atomic Updates vs Read-Modify-Write

**The Problem with Read-Modify-Write:**
```
Person A reads click_count = 100
Person B reads click_count = 100
Person A writes click_count = 101
Person B writes click_count = 101
Result: Lost one click (race condition)
```

**The Solution with Atomic Updates:**
```python
UpdateExpression='SET click_count = click_count + :val'
```
- DynamoDB handles coordination internally
- Multiple concurrent updates don't lose data
- Critical for high-traffic applications

---

### Partition Keys & Access Patterns

**Why `short_code` as partition key?**

Access pattern: User visits `yoursite.com/abc123` → need to find long_url

- We KNOW: `short_code = "abc123"` (from the URL)
- We DON'T KNOW: `long_url` (that's what we're looking up)
- Therefore: Partition key must be `short_code`

**Partition key determines:**
- How data is organized physically
- What queries can be fast (<10ms)
- What attributes can be used for direct lookups

You can ONLY do fast lookups by partition key. Everything else requires slow scans.

## URL Shortener Data Model Design

### Schema
```json
{
  "short_code": "abc123",          // Partition key
  "long_url": "https://example.com/very/long/path",
  "created_at": "2025-10-27T22:45:00Z",
  "click_count": 0
}
```

### Short Code Generation Strategy

**Option chosen:** Random generation
```python
import random
import string

def generate_short_code(length=6):
    chars = string.ascii_letters + string.digits  # a-z, A-Z, 0-9
    return ''.join(random.choices(chars, k=length))
```

**Why random?**
- 62^6 = 56 billion possible combinations
- Simple to implement
- Low collision probability (~0.001%)

---

### Collision Handling

**Problem:** What if random generator produces a code that already exists?

**Solution:** Conditional put with retry logic
```python
table.put_item(
    Item={...},
    ConditionExpression='attribute_not_exists(short_code)'
)
```

**How it works:**
- Try to create item, but ONLY if `short_code` doesn't exist yet
- If collision detected → DynamoDB rejects it
- Generate new random code and try again
- Max 5 attempts (extremely unlikely to need all 5)

**Two different problems clarified:**
1. **Collision when creating:** Two people try to create same short_code → handled by conditional put
2. **Race condition when clicking:** Two people click same link simultaneously → handled by atomic updates
