## What I Built

### Project: S3-Triggered Lambda Function

Created a Lambda function that automatically executes when files are uploaded to S3.

**Architecture:**
```
User uploads file → S3 Bucket → S3 Event → Lambda Function → CloudWatch Logs
```

**Components:**
- **Lambda Function:** `chris-first-lambda` (Python 3.12)
- **S3 Bucket:** `chris-lambda-triggers`
- **Trigger:** All object create events
- **Logs:** CloudWatch Log Group

**Code:**
```python
import json

def lambda_handler(event, context):
    # Log the entire event to see what S3 sends us
    print("Received event:", json.dumps(event))
    
    # Extract S3 bucket and file info from the event
    bucket = event['Records'][0]['s3']['bucket']['name']
    key = event['Records'][0]['s3']['object']['key']
    size = event['Records'][0]['s3']['object']['size']
    
    print(f"File uploaded to bucket: {bucket}")
    print(f"File name: {key}")
    print(f"File size: {size} bytes")
    
    return {
        'statusCode': 200,
        'body': json.dumps(f'Successfully processed {key}')
    }
```

**Test Results:**
- Uploaded 1.96 MB screenshot to S3
- Lambda automatically triggered within milliseconds
- Successfully logged file metadata to CloudWatch
- Execution time: ~50-100 milliseconds
- Cost: ~$0.0000001 per execution

## Key Insights

### Lambda vs EC2 Cost Comparison

For the test execution:
- **Lambda:** 50 ms of compute time
- **EC2:** Would run 24/7 = 86,400,000 ms per day
- **Cost difference:** EC2 is 1,728,000x more expensive for this sporadic workload

**Lesson:** Lambda makes sense for event-driven, short-lived workloads. EC2 makes sense for always-on applications or jobs exceeding 15 minutes.

### When to Use Lambda

**Good use cases:**
- Processing file uploads (resize images, scan for viruses)
- API backends (URL shorteners, webhooks)
- Scheduled tasks (daily reports, data cleanup)
- Event-driven workflows (order processing, notifications)

**Not good use cases:**
- Long-running jobs (>15 minutes) → use EC2 or Fargate
- Always-on services with consistent traffic → EC2 may be cheaper
- Applications requiring full server customization

### Understanding the `event` Parameter

The `event` parameter contains data about what triggered the Lambda:
- S3 trigger → bucket name, file key, file size, event time
- API Gateway trigger → HTTP method, headers, body, query params
- CloudWatch Events → scheduled event data

**This is how Lambda knows what to do** - the trigger passes context in the `event` object.
