## Architecture Overview

**Three-tier serverless architecture:**
```
POST /shorten → API Gateway → Lambda (create) → DynamoDB → Return short_code
GET /{short_code} → API Gateway → Lambda (get) → DynamoDB → 302 Redirect
```

**Services Used:**
- **DynamoDB:** NoSQL database storing URL mappings (short_code → long_url)
- **Lambda:** Two serverless functions (url-shortener-create, url-shortener-get)
- **API Gateway:** REST API exposing HTTP endpoints
- **IAM:** Roles granting Lambda permissions to access DynamoDB

---

## Technical Implementation

### 1. DynamoDB Table Design
**Table Name:** `url-shortener`
- **Partition Key:** `short_code` (String) - enables O(1) lookups
- **Attributes:** 
  - `short_code`: Unique 6-character identifier
  - `long_url`: Original destination URL
  - `click_count`: Number of times the short URL was accessed
  - `created_at`: ISO 8601 timestamp

**Why NoSQL?** Fast key-value lookups, scales horizontally, pay-per-request pricing model fits sporadic traffic patterns.

### 2. Lambda Functions

**url-shortener-create (POST /shorten):**
- Accepts JSON: `{"long_url": "https://example.com"}`
- Generates random 6-character short_code using alphanumeric characters
- Stores mapping in DynamoDB with `put_item()`
- Returns: `{"short_code": "abc123", "short_url": "https://api.../prod/abc123", "long_url": "..."}`

**url-shortener-get (GET /{short_code}):**
- Extracts short_code from URL path parameter
- Queries DynamoDB with `get_item(Key={'short_code': '...'})`
- Increments click_count atomically using `update_item()` with `ADD` expression
- Returns HTTP 302 redirect with `Location` header pointing to long_url

**Key Learning:** Lambda functions are stateless and event-driven. Each invocation processes one request independently.

### 3. API Gateway Configuration

**Endpoints:**
- `POST /shorten` → Triggers url-shortener-create Lambda
- `GET /{short_code}` → Triggers url-shortener-get Lambda (path parameter)

**Integration Type:** Lambda Proxy Integration (enabled)
- API Gateway passes entire HTTP request to Lambda (headers, body, query params)
- Lambda controls full HTTP response (status code, headers, body)

**Deployment Stage:** `prod` (production environment)

### 4. HTTP Redirect Mechanics

**Status Code Decision: 301 vs 302**
- **301 (Permanent Redirect):** Browser caches redirect, may bypass server on repeat visits
- **302 (Temporary Redirect):** Browser always checks server, better for analytics ✅ (I chose this)

**Implementation:**
```python
return {
    'statusCode': 302,
    'headers': {
        'Location': long_url  # Browser automatically redirects here
    },
    'body': json.dumps({...})
}
```

## Key Concepts Learned

### 1. Serverless Architecture Benefits
- **No server management:** AWS handles scaling, patching, availability
- **Pay-per-request pricing:** Only charged for actual invocations (not idle time)
- **Auto-scaling:** Handles 1 request/day or 10,000 req/sec without configuration changes
- **Event-driven:** Functions triggered by API Gateway HTTP requests

### 2. DynamoDB Operations
- **put_item():** Create new items (short URL mappings)
- **get_item():** Retrieve items by partition key (O(1) lookup)
- **update_item():** Atomic increment of click_count using `ADD` expression
  - Prevents race conditions when multiple users click simultaneously
  - `UpdateExpression='ADD click_count :inc'` with `ExpressionAttributeValues={':inc': 1}`

### 3. API Gateway Path Parameters
- `/{short_code}` defines dynamic URL segment
- Lambda receives path parameter in `event['pathParameters']['short_code']`
- Enables clean URLs: `/abc123` instead of `?code=abc123`

### 4. IAM Permissions Model
- Lambda execution role needs:
  - `dynamodb:PutItem` (for create function)
  - `dynamodb:GetItem` (for get function)
  - `dynamodb:UpdateItem` (for incrementing clicks)
- **Principle of least privilege:** Grant only necessary permissions

## Debugging & Problem-Solving

### Issue 1: Hardcoded "yourdomain.com" in Response
**Problem:** `short_url` returned `https://yourdomain.com/{short_code}` instead of actual API URL

**Root Cause:** Placeholder text in url-shortener-create Lambda line 35

**Solution:** 
1. Found Invoke URL in API Gateway → Stages → prod
2. Updated Lambda code to use actual URL: `https://3xoo2ucyxk.execute-api.us-east-2.amazonaws.com/prod`
3. Deployed Lambda function
4. Verified fix with new curl test

**Learning:** Always replace placeholder values with production configuration before deployment

### Issue 2: Understanding 301 vs 302 Status Codes
**Confusion:** Which redirect code to use?

**Resolution:**
- **301 = Permanent Redirect:** "This URL has moved forever"
- **302 = Temporary Redirect:** "This URL has moved temporarily"

**Decision:** Chose **302** because:
- Prevents aggressive browser caching
- Ensures every click goes through server (accurate analytics)
- Common pattern for URL shorteners (bit.ly uses 302)
